# Documentation Truthfulness Doctrine — Candidate Disposition Ledger

**Status**: Implemented (ACT 2.8)

This document supplements [documentation-truthfulness.md](documentation-truthfulness.md) with the candidate disposition ledger system.

## Purpose

A ledger that tracks the disposition of every generated claim candidate, making the system honest about every candidate's fate.

## Ledger File

**Location**: `docs/claims/docs_claim_dispositions.csv`

## Ledger Columns

| Field | Description |
|-------|-------------|
| `candidate_id` | Reference to DOC-CAND-xxx in generated candidates |
| `disposition` | How the candidate was handled |
| `claim_id` | For registered claims, the DOC-CLAIM-xxxx ID |
| `covered_by_claim_id` | For covered candidates, the covering DOC-CLAIM-xxxx |
| `reason_code` | Why this disposition was chosen |
| `reviewed_at` | Date of review (ISO format) |
| `reviewer_notes` | Human explanation |

## Allowed Dispositions

| Disposition | Meaning |
|-------------|---------|
| `registered_existing_claim` | Already in claims registry |
| `registered_new_claim` | Newly promoted to registry |
| `covered_by_existing_claim` | Covered by broader existing claim |
| `duplicate_candidate` | Duplicate of another candidate |
| `false_positive` | Not actually a claim |
| `heading_or_table_fragment` | Heading/table, not a claim |
| `too_granular` | Too specific for registry |
| `historical` | From historical doc |
| `stale` | From stale doc |
| `docs_only_context` | Docs-internal context only |
| `implementation_detail_not_claim` | Implementation detail |
| `policy_statement_only` | Non-normative policy statement |
| `backlog_future_claim` | Future candidate, not yet promoted |
| `needs_new_claim` | Candidate needs promotion but deferred |
| `ignored_by_policy` | Intentionally ignored by policy |

## Reason Codes

| Code | Meaning |
|------|---------|
| `already_registered` | Candidate is registered to a claim |
| `covered_by_broader_claim` | Covered by broader claim |
| `duplicate_same_doc` | Duplicate in same doc |
| `duplicate_cross_doc` | Duplicate across docs |
| `generated_from_heading` | From heading, not prose |
| `generated_from_table_fragment` | Table fragment, not a claim |
| `historical_doc` | From historical document |
| `stale_doc` | From stale document |
| `non_normative_description` | Description, not a claim |
| `implementation_detail` | Implementation detail |
| `policy_statement` | Non-normative policy |
| `low_value_context` | Low-value context |
| `not_a_claim` | Does not assert behavior |
| `too_granular_for_registry` | Too granular |
| `requires_future_human_review` | Needs human review |
| `promoted_to_registry` | Promoted to new claim |

## Key Rules

- Every generated candidate must have exactly one disposition
- `registered_existing_claim` must point to existing DOC-CLAIM-xxxx
- `registered_new_claim` must point to new DOC-CLAIM-xxxx
- `covered_by_existing_claim` must point to existing DOC-CLAIM-xxxx
- `ignored_by_policy` requires non-empty reason_code and notes
- `needs_new_claim` allowed only as temporary debt

## Verifier

**Script**: `scripts/verify_docs_claim_candidate_dispositions.py`

**Validation checks**:
- Ledger structure and schema validation
- Cross-reference to registry and candidates
- Every candidate has exactly one disposition
- Semantic combination validation
- Runs in local gate, verify.yml, and harbor.yml

## Candidate vs Claim Distinction

- `candidate`: Generated output from scanner, broader than registry
- `claim`: Formal registry entry with evidence tracing
- Not every candidate needs to be a claim
- The disposition ledger tracks what happened to each candidate
